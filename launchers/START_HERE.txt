IndustrialMind - double-click launchers (nothing to type)
=========================================================

Prerequisite (already done on your laptops): the project folder has its .venv, and config/lab.env has the four
addresses and the shared secret. These launchers only START things; they install nothing.

WHICH FILE ON WHICH LAPTOP (all inside the project folder, in "launchers")
  Laptop 1  Mac      middleware + dashboard + capture   launchers/laptop1_mac_middleware.command
  Laptop 2  Windows  PLC + capture                      launchers/laptop2_win_plc.bat
  Laptop 3  Mac      SCADA operator                     launchers/laptop3_mac_scada.command
  Laptop 4  Windows  attacker menu                      launchers/laptop4_win_attacker.bat
  Backup    any      the WHOLE system on ONE computer   launchers/ONE_PC_BACKUP.command (Mac)
                                                        launchers/ONE_PC_BACKUP.bat     (Windows)

ATTACK BUTTON PANEL (menu-driven, click a button per attack)
  Laptop 4  Windows  launchers/laptop4_attack_panel.bat   (Mac/Linux: launchers/attack_panel.command)
  It opens a page in the browser on THAT laptop (http://127.0.0.1:5070, local only): one button per attack with what it
  does and the answer to expect, Run all, Stop, and the attack's live output. It runs the same launcher as the command
  line, so the addresses and secret come from config/lab.env. One attack at a time. The dashboard has no attack buttons.
  In the one-computer backup, press B in its menu to open the same panel against this computer.

ORDER (the real 4-laptop demo)
  1. Laptop 2:  double-click laptop2_win_plc.bat       -> a PLC window and a capture window open
  2. Laptop 1:  double-click laptop1_mac_middleware.command
                                                        -> dashboard, middleware and capture windows open,
                                                           and the dashboard opens in the browser
  3. Laptop 3:  double-click laptop3_mac_scada.command  -> waits for the middleware, then starts SCADA
  4. Wait about 2 minutes (the physical model warms up)
  5. Laptop 4:  double-click laptop4_attack_panel.bat   -> click a button per attack (or laptop4_win_attacker.bat for the
                                                           typed menu: a number per attack, A = all, Q = quit)
  6. Stop: close the windows in the reverse order (attacker, SCADA, middleware/dashboard, PLC).
     To bring the plant back to normal on Laptop 3:  bash scripts/run.sh scada --restore   (it also self-restores)

FIRST TIME ON A MAC
  If macOS refuses to open a .command file ("cannot be opened" / "unidentified developer"):
  right-click the file -> Open -> Open. Or run once in Terminal:   chmod +x launchers/*.command
  (If a file was unzipped by Finder you may also need:   xattr -dr com.apple.quarantine <project folder>)

FIRST TIME ON WINDOWS
  Double-click the .bat. If a SmartScreen box appears: More info -> Run anyway.
  The capture needs Wireshark (tshark) installed; the capture adapter number is the CaptureIface line at the top of
  launchers/laptop2_win_plc.ps1 (it is 4 on your laptop; `tshark -D` lists the numbers).
  On Laptop 1 the capture interface is en0; to change it, edit IFACE at the top of laptop1_mac_middleware.command.

IF THE MIDDLEWARE SAYS "Host is down" FOR THE PLC
  Laptop 1 cannot see Laptop 2 on the Wi-Fi (not a code problem). From Laptop 1:  ping -c 3 <Laptop 2 address>
  If it fails, put all laptops on the same Wi-Fi or one phone hotspot, and update the addresses in config/lab.env.

BACKUP: EVERYTHING ON ONE COMPUTER
  Double-click ONE_PC_BACKUP.command (Mac) or ONE_PC_BACKUP.bat (Windows). It starts the PLC, dashboard, middleware
  and SCADA on this machine, opens the dashboard, records the packets (if tshark is installed), and shows the same
  attack menu. Q stops everything. All traffic stays on this computer, so it cannot show packets crossing between
  laptops - say that if you present it. Logs: logs/one_pc_demo/.
